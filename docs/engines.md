## smpt

- **What it checks.** Reachability only: a condition on a marking (`state`), `EF φ` and `AG φ` where
  φ has no temporal operator (the contest's two reachability categories). Anything else is UNKNOWN
  with the warning `smpt_checks_reachability_not_<logic>`: never a guess. The selector classes
  `EF φ` and `AG φ` as reachability questions too (`asks_reachability`).
- **Build.** SMPT is fetched at a pinned commit (the repository's latest tag, v4.0.0, is older than
  the 5.0 of its `setup.py`). It needs z3 (Debian's, 4.8.12), the Python library `sexpdata`
  (hash-pinned in `engines/smpt/requirements.txt`) and the Tina toolbox: `ndrio` to read PNML,
  `reduce` and `walk`. Tina's binary is downloaded at build time and its SHA-256 is checked, so
  the build breaks if the authors publish another file under the same name. Tina is distributed by
  LAAS-CNRS under its own licence (free for non-commercial use): the image is built locally and
  not redistributed by this project. LattE, Octant (OCaml) and MiniZinc are not in the image: the
  polyhedral reduction runs without them, and the net is not shrunk as much as in the contest.
- **Options.** The contest's: `--auto-reduce --project --mcc --methods DUMMY` (in `--mcc` mode the
  tool chooses its methods), `--global-timeout` a little below our own kill. A request with
  `reduce: false`, and formulas that use the `deadlock` atom (which the `--mcc` simplifier does not
  know), run without reductions and with an explicit list of methods (state equation, BMC,
  k-induction, PDR). Formulas run in groups of the same kind (deadlock atom or not, fireability
  atoms or not), each group within an equal share of the time.
- **The PNML.** SMPT reads the places' names only when the file declares the PNML namespace; the
  adapter gives it a copy with the namespace declared (same net, same ids). The ids it prints are
  `q0`, `q1`, ... (ours are free text) and are mapped back.
- **Colored nets.** Not supported (no `mcc` unfolder in the image). Given a colored net, the adapter
  answers UNKNOWN with `colored_nets_not_supported`: the first conformance run showed that SMPT
  reads a colored net as if it were P/T and answers FALSE where the answer is TRUE.
- **Traces.** None: SMPT gives a marking (`--show-model`), not a firing sequence.
- **Conformance.** All 11 reachability answers on `TwoPhaseLocking-PT-nC00004vN` and the 3 by hand
  equal the references; see `docs/conformance-report.md`.

## tapaal (verifypn)

- **Build.** From source in a multi-stage image on Debian 12 (spot 2.11.3, which the tool fetches,
  ships files generated by automake 1.16, absent from Debian 13). The tool's CMake downloads its
  dependencies (ptrie by commit, rapidxml, spot, glpk) while building, pinned by the tool's
  commit but without checksums: the one supply-chain gap of this image. The image is built
  locally, never redistributed by this project; whoever publishes it must offer the source (GPL).
- **Formulas.** The contest's property XML is verifypn's native query format, so the adapter
  writes it with `app/domain/mcc_xml.py` (tested by reading back every contest formula of the
  corpus unchanged). One process per formula: each gets an equal share of the remaining time and
  its own trace. The rendered XML is kept in `rendered`.
- **Reductions.** verifypn reduces by default; a request with `reduce: false` runs it with `-r 0`.
- **Answers.** `Query is satisfied.` is TRUE, `Query is NOT satisfied.` FALSE, anything else
  UNKNOWN; a timeout is TIMEOUT; a process killed by SIGKILL is OOM. Never FALSE by default.
- **Traces.** verifypn prints transitions with `-t`. They are given as is on P/T nets, with
  `loop_start` for a loop. On colored nets verifypn unfolds the net, so its transition names are
  not those of the net given: no trace, warning `trace_not_given_for_colored_net`. For a TRUE
  answer the trace is a witness, not a counterexample, and says so in a warning.
- **Conformance** (this integration, 2 contest instances from the corpus, first 4 formulas of each
  Boolean examination, 2 GB, 300 s, against the contest's reference answers): 40 of 48 answers
  equal the reference. The 8 others are not disagreements but non-answers within our limits: 3
  OOM and 2 TIMEOUT on the colored instance (CTL cardinality, LTL fireability), where the contest
  itself had no answer for two of them. No TRUE where the reference says FALSE, or the reverse.
  The systematic matrix across engines is the conformance suite (#38).

## itstools

- **Pinning.** The authors publish the product only as "the latest build" at a fixed URL
  (`lip6.github.io/ITSTools`), with no versioned download. The image fetches it and fails unless
  its SHA-256 is the one recorded in the Dockerfile; when upstream publishes a new build, the
  build breaks on purpose and a maintainer updates the checksum and the version (read from the
  name of the tool's plugins) together. Licence GPL-3.0: built locally, not redistributed.
- **Run.** The contest wrapper's way: a folder with `model.pnml` and `<Examination>.xml`, the
  contest options (`-its -order META -manyOrder -smt`; without them most CTL and LTL formulas stay
  unsolved) and the JVM options of the product's own `.ini` (given again, because any `-vmargs`
  replaces them). The formulas of a request are grouped by examination (state, CTL or LTL; cardinality
  or fireability by their atoms) and each group is one run, so the tool shares its reductions
  inside a group. Ids written for the tool are `q0, q1, ...`, mapped back, so no id of ours can
  confuse its output.
- **Deadlock.** The tool crashes on the `deadlock` atom and a crash loses the whole group, so the
  adapter writes it as "no transition is fireable" (all the net's transitions in one `is-fireable`
  atom, the contest's own way to say any of them): the same meaning in atoms the tool reads. This
  is the only rewriting of a formula, and the rewritten XML is the one kept in `rendered`.
- **Sandbox.** The product tries to `chmod +x` its bundled binaries each time it runs, which a
  read-only root refuses. They are executable from the build, and a ten-line `LD_PRELOAD` shim
  (`engines/itstools/keepmode.c`, used for the tool's process only) answers success to a chmod of
  a file under `/opt/tool` that is already executable, and passes every other call on.
- **Answers.** `FORMULA <id> TRUE|FALSE` lines. A formula the tool left unsolved is UNKNOWN. When
  the time is over the process is killed, TIMEOUT is given to the formulas without a line, and what
  was solved before the kill is kept. SIGKILL is OOM.
- **Reductions.** The tool always reduces: a request with `reduce: false` is run as usual and
  each answer carries the warning `reductions_cannot_be_disabled`.
- **Traces.** None: in this mode the tool gives no counterexample, and each answer says so
  (`no_counterexample_from_its_tools`).
- **Conformance** (same protocol as Tapaal, 120 s per examination, 2 GB): 44 of 48 answers equal
  the contest's reference answers, none differs. The 4 others are timeouts on the colored
  instance, on formulas the reference has no answer for either.

## native

The analyses and reductions of the platform (`GET /v1/operations` lists them), run in a container like any
engine (ADR 0019). Nothing is fetched or built: the image holds the platform's domain code. The
version is bumped, in the registry and in the Dockerfile, with every change of an algorithm,
because results are cached by tool version; a test compares the sources with the digest in
`engines/native/DIGEST` and fails until the version is bumped (`scripts/native_digest.py`). P/T nets only for now.
