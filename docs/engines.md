## tapaal (verifypn)

- **Build.** From source in a multi-stage image on Debian 12 (spot 2.11.3, which the tool fetches,
  ships files generated by automake 1.16, absent from Debian 13). The tool's CMake downloads its
  dependencies (ptrie by commit, rapidxml, spot, glpk) while building, pinned by the tool's
  commit but without checksums: the one supply-chain gap of this image. The image is built
  locally, never redistributed by this project; whoever publishes it must offer the source (GPL).
- **Formulas.** The contest's property XML is verifypn's native query format, so the adapter
  writes it with `app/domain/mcc_xml.py` (tested by reading back every contest formula of the
  corpus unchanged). One process per formula: each gets an equal share of the remaining time and
  its own trace. The rendered XML is kept in `rendered`.
- **Answers.** `Query is satisfied.` is TRUE, `Query is NOT satisfied.` FALSE, anything else
  UNKNOWN; a timeout is TIMEOUT; a process killed by SIGKILL is OOM. Never FALSE by default.
- **Traces.** verifypn prints transitions with `-t`. They are given as is on P/T nets, with
  `loop_start` for a loop. On colored nets verifypn unfolds the net, so its transition names are
  not those of the net given: no trace, warning `trace_not_given_for_colored_net`. For a TRUE
  answer the trace is a witness, not a counterexample, and says so in a warning.
- **Conformance** (this integration, 2 contest instances from the corpus, first 4 formulas of each
  Boolean examination, 2 GB, 300 s, against the contest's reference answers): 40 of 48 answers
  equal the reference. The 8 others are not disagreements but non-answers within our limits: 3
  OOM and 2 TIMEOUT on the colored instance (CTL cardinality, LTL fireability), where the contest
  itself had no answer for two of them. No TRUE where the reference says FALSE, or the reverse.
  The systematic matrix across engines is the conformance suite (#38).
