# Releasing

One version number for the API, the UI and the images, following semantic versioning for the
public contract of `docs/api-versioning.md`.

## Process
1. `main` is green (`make check`, CI) and `docs/` describe what is in it.
2. Choose the version from the commits since the last tag: a `feat:` bumps the minor version, a
   `fix:` the patch, a breaking change the major version (and a new API prefix, see the policy).
3. Set it in `api/pyproject.toml`, `api/app/__init__.py` and `ui/package.json`; commit
   `chore: release X.Y.Z` through a pull request.
4. Tag `vX.Y.Z` on `main` and push the tag. The `release` workflow builds the images and creates a
   GitHub release whose notes are generated from the conventional commits (git-cliff,
   `cliff.toml`).
5. `CHANGELOG.md` is regenerated by `make changelog` (needs git-cliff) and committed with the
   release.

Commit messages are the source of the release notes: one concern per commit, a conventional
prefix, and the issue in the pull request description (`Closes #N`).
